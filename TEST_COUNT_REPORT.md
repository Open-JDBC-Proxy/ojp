### How CSV Parameterization Works

Integration tests in OJP use JUnit 5's `@ParameterizedTest` with `@CsvFileSource` to run the same test multiple times with different database configurations. Each row in a CSV file represents a different test execution with parameters like:
- Database driver class
- Connection URL
- Username/password
- XA transaction flag
- Record count thresholds (for performance tests)

For example, the `mysql_mariadb_connection.csv` file has 2 rows, and 76 test methods reference it, resulting in 152 total test executions (76 tests × 2 configurations).

## Methodology

This count was generated by:
1. Scanning all Java test files (files ending in `Test.java` or `Tests.java` in `/src/test/` directories)
2. Using regex pattern matching to identify `@Test` and `@ParameterizedTest` annotations
3. For parameterized tests, extracting the CSV filename from `@CsvFileSource` annotations
4. Counting the number of data rows in each CSV file (no headers assumed)
5. Multiplying the number of parameterized test methods by their respective CSV row counts

### Test Classification
Tests are classified as integration or unit tests using the following rules:
- **Integration tests:** Tests that use CSV files containing database connections (identified by keywords like 'connection', 'mysql', 'postgres', 'oracle', etc. in the CSV filename)
- **Integration tests:** Tests in files with "Integration" in the filename
- **Unit tests:** All other tests
